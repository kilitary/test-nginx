Этот репозиторий содержит настройку Docker‑Compose с тремя контейнерами Nginx‑reverse‑proxy (`proxy1`, `proxy2`, `proxy3`), которые перенаправляют запрос к простому HTTP‑сервису Flask (`simple‑http`).

Цель конфигурации:
1. **Сцепить прокси** – `proxy1 ➜ proxy2 ➜ proxy3 ➜ simple‑http`.
2. **Запретить клиенту задавать** заголовок `X‑Real‑IP`. Если запрос попадает в прокси, в котором заголовок `X‑Real‑IP` ещё не присутствует, прокси добавляет его, используя реальный IP клиента (`$remote_addr`).
3. **Накопить заголовок `X‑Forwarded‑For`**, чтобы конечный сервис видел всю цепочку переходов.

Ниже перечислены шаги по сборке, запуску и проверке поведения.

---

## Предварительные требования
- Docker Engine (или Docker Desktop) с поддержкой Compose v2.
- `curl` (или любой HTTP‑клиент), установленный на хосте.

## 1. Сборка и запуск стека
```bash
# Из корня проекта (p:/test-nginx)
cd p:/test-nginx

# Собрать образ simple‑http и запустить все сервисы
docker compose up -d --build
```
Docker загрузит образ `nginx:alpine`, соберёт образ `simple‑http` (Python Flask) и запустит четыре контейнера:
- `proxy1` — слушает **localhost:8081**
- `proxy2` — слушает **localhost:8082**
- `proxy3` — слушает **localhost:8083**
- `simple‑http` — внутренний сервис на порту 8080 (проброшен как 8084, не используется напрямую в тестах)
